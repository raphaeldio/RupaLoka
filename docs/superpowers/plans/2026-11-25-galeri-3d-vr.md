# Rencana Implementasi — Galeri 3D + Penampil Objek + VR (F-060)

- Spesifikasi: `docs/superpowers/specs/2026-11-25-galeri-3d-vr-design.md` (§ di bawah merujuk ke sini)
- Purwarupa alur kamera: `mocks/galeri-kamera/` (sumber port untuk `cameraFlow.ts` dan rig kamera)
- Cabang: `feat/galeri-3d` (dibuat dari `main` setelah `feat/masukan-juri` digabung)
- ID tugas: **T-110 … T-129** (fase baru "Fase 3d" di `docs/TASKS.md`)

## Tujuan

Rute `/kota/:cityId/galeri` menampilkan lorong melingkar berisi objek koleksi Bandung. Pengguna berjalan, mendekat, dan memeriksa objek dengan hotspot bersumber, di desktop, ponsel, dan Quest (WebXR). Seluruh fitur ada di balik flag `viewer3d` + `premium_content` dan dimuat lambat.

## Prasyarat dan urutan

- **Mulai setelah tugas kode P0 milik HR selesai** (keputusan sesi: "setelah semua P0"). Tugas konten KH yang masih terbuka (T-030 … T-035, T-081 … T-085) berjalan paralel dan **tidak** menghalangi rencana ini.
- Tugas 1–7 (dokumen, flag, backend, konten) tidak butuh paket 3D dan bisa dikerjakan lebih dulu.
- Tugas 8 memasang paket 3D. Tugas 9–17 membangun galeri. Tugas 18 (aset Blender) bisa paralel sejak Tugas 5 selesai. Tugas 19–20 adalah penutup.
- Setiap tugas diakhiri dengan lint + uji yang relevan lolos dan satu commit kecil (Conventional Commits, rujuk ID).

## Dua penyesuaian terhadap spesifikasi (dicatat di spesifikasi pada commit yang sama)

1. **Penyajian GLB.** Aset konten saat ini disajikan backend di `/api/assets/*` (Render). Layanan Render gratis tertidur, dan *cold start*-nya akan membuat unduhan ±15 MB gagal atau lambat. Karena itu:
   - GLB tetap disimpan di `content/assets/models/` (sumber kebenaran, divalidasi).
   - Plugin Vite kecil menyalinnya ke `dist/models/` saat build dan menyajikannya di `/models/*` saat dev.
   - Vercel menyajikannya dari CDN dengan `Cache-Control: immutable`.
2. **Parameter cincin ditulis eksplisit di `gallery.yaml`** (`layout.radius`, `layout.slots`, `layout.first_d`), bukan dihitung dengan rumus di dua bahasa. Frontend dan validator membaca angka yang sama. Validator memeriksa `slots ≥ jumlah exhibits` dan `radius ≥ 6`.

## Tugas 3 — T-112 Pembaca GLB (`feat:`)

**Uji dulu** (`backend/tests/test_glb.py`). Fixture GLB dibuat di dalam tes, bukan file biner:

```python
def make_glb(nodes: list[dict]) -> bytes:
    doc = json.dumps({"asset": {"version": "2.0"}, "nodes": nodes}).encode()
    doc += b" " * (-len(doc) % 4)
    body = struct.pack("<II", len(doc), 0x4E4F534A) + doc
    return struct.pack("<III", 0x46546C67, 2, 12 + len(body)) + body
```

Kasus uji:
- `read_nodes(make_glb([{"name": "hotspot_tabung", "translation": [0, .7, .2]}]))` → `{"hotspot_tabung": (0, .7, .2)}`.
- Node tanpa `translation` → `(0, 0, 0)`.
- Magic salah → `GlbError`.
- Versi ≠ 2 → `GlbError`.
- Chunk pertama bukan JSON → `GlbError`.

**Implementasi** `backend/app/glb.py`:
- `read_nodes(data: bytes) -> dict[str, tuple[float, float, float]]` dan `read_nodes_file(path: Path)`.
- Hanya membaca header 12 byte dan chunk JSON. Posisi yang diambil adalah translasi lokal; anak dari node berinduk tidak dikomposisi. Batasan ini didokumentasikan: Blender harus mengekspor empty `pedestal_N`/`hotspot_*` di akar, atau langsung di bawah objek akar tanpa transformasi.

`pytest -q tests/test_glb.py`, `ruff`, `black`. Commit: `feat: T-112 baca node GLB untuk validasi`.

## Tugas 5 — T-114 Validasi aset galeri (`feat:`)

Di `content_loader.py`, untuk kota yang punya galeri, setiap aturan diberi uji dengan GLB buatan `make_glb` yang ditulis ke `tmp_path`:

1. File `room.model` dan `item.model.src` ada di bawah `content/`.
2. Ukuran objek ≤3 MB dan ruangan ≤8 MB. Pelanggaran = galat; ukuran >80 % batas = peringatan.
3. Total `room` + semua model exhibits ≤15 MB.
4. Setiap `hotspots[].id` punya node `hotspot_<id>` di GLB objek.
5. GLB ruangan punya node `pedestal_1` … `pedestal_{slots}`. Posisi XZ masing-masing berada dalam 0,1 m dari `ring_point(i)`.
6. `poster` ada di bawah `content/`.

`ring_point(i)` di Python adalah rumus yang sama dengan `cameraFlow.ts`:
- `d = first_d + i·2πR/slots`
- `a = d/R`
- sisi `s = -1` bila `i` genap, `+1` bila ganjil
- `p = (-R + R·cos a, -R·sin a) + s·1.9·(cos a, -sin a)`

**Vektor uji bersama:** `content/bandung/gallery.yaml` dengan `R=6, slots=12, first_d=3`. Posisi `pedestal_1` dan `pedestal_2` (dihitung sekali) dicantumkan sebagai konstanta yang sama di `test_content_loader.py` dan `cameraFlow.test.ts`. Kalau salah satu rumus berubah, kedua uji gagal.

Commit: `feat: T-114 validasi GLB, ukuran, hotspot, pedestal`.
